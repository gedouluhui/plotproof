# CA1 — actual-save capture semantics and implementation plan

Status: development amendment, 2026-11-18. This document governs new capture code only. It does not rewrite `b0-freeze-r17`, claim that its preregistration predicted these changes, or authorize holdout generation. Before B2, the operative preregistration/manifest must explicitly incorporate reviewed amendments and receive a new freeze. Old evidence remains attributable to its old revision.

## Why the capture contract needs an amendment

`artifacts/b1/capture-semantics-probe.json`, generated by `spikes/b1_capture_semantics_probe.py`, records two real counterexamples. A Rectangle with source/getter alpha values 0.6 and 0.6 produces PDF fill alpha 0.6 and gray RGB 102 over white, not the getter-product model's 0.36 and gray 163. In ordinary layout, the actual PDF save computes a different tight crop from the Agg pre-draw. The constrained-layout control does not establish universality.

## Normative CA1 rules

### Alpha

Record raw source/getter alpha separately from the graphics context at the actual PDF drawing call. At `RendererPdf.draw_path` or `draw_text`, retain `gc_alpha`, `gc_forced_alpha`, and the supplied RGBA color. Match `RendererPdf.check_gc`:

- Forced alpha: effective fill/text alpha is `gc_alpha`, independent of color alpha.
- Unforced fill: use the supplied fill alpha, or 1 for a 3-channel fill.
- Unforced text: use foreground color alpha.

A future adapter to the pure core's multiplicative fields uses explicitly named *normalized renderer factors* `(effective_alpha, 1.0)`, never relabels them as raw source getter values, and retains the raw values/forced flag as provenance. The pure core formula and thresholds are unchanged. Images and per-instance collection opacity require separate capture; their semantics are not inferred from patch factors.

### Coordinates and tight crop

The Agg pre-draw bbox is provenance only. Observe the actual `Figure.get_tightbbox` call made inside this save and apply the resolved scalar pad to its returned inches. With crop origin `(q_x,q_y)` inches and original DPI `D`, the source display pullback of a final vector-backend point `(x,y)` is `(x*D/72 + q_x*D, y*D/72 + q_y*D)`. Plain save uses q=(0,0). Final PDF events already use bottom-left PDF points; no y flip is added.

Only one unambiguous saving-time crop call is accepted in this initial adapter. Unknown/multiple crop calls, uncertain renderer coordinates, or rasterized text produce a capture issue, not a guessed origin. A target PDF page is independently read by the bounded PDFium reader and its size must agree with the observed save crop (within the observed binary32 page-size representation). No post-save tightbbox call is allowed.

### Event and source identity

Separate deterministic source enumeration from actual emitted drawing events. Source IDs share one space for Text and Patch objects: depth-first artist-child traversal, with explicit Text bbox patches and Table Cell text added where ordinary children omit them. Dynamic text/patch objects encountered during drawing are appended in first-observed order. IDs are local to one capture, not cross-figure identities.

Painting order is the order of real target-bound PDF renderer events, not zorder or outer artist method entry. A Text's own background patch is emitted before the Text; multiline Text may emit several events carrying one source ID. A filled path may emit several pieces; consumers must not silently merge those into an opaque rectangle. Unpainted Text still remains in the inventory with no emitted event; this layer does not yet compute the full §7.1 predicate or source_units_total.

Each event carries its renderer kind, source ID or null, sequence, source class, optional actual PDF bbox, applied alpha record and raw source alpha. Text events retain the actual string, font size, angle and source text. This layer is deliberately not a complete source manifest, alignment result or detector report: font cmap collection, clip semantics, supported filled geometry, table/inset/image/collection mapping and final unit enumeration are separate responsibilities.

### Fail-closed coverage and safety

Record explicit issues for image/collection/gouraud emissions not captured by this layer, unsupported text rendering (math/TeX/raster/path effects), nonrectangular clipping, wrapped text whose emitted content differs from source, unassociated material events and ambiguous crop events. `capture_issues` is never discarded or interpreted as PASS. No high-confidence evidence may be built from an incomplete event mapping.

The adapter is version-checked for Matplotlib 3.10.8, FigureCanvasAgg and native PDF output. It records into an owned bounded memory buffer, not arbitrary code or remote services. Calling it on a live Figure invokes that Figure's trusted local Python drawing code, just as savefig does; this is not an API for executing untrusted Python. Unrelated concurrent Matplotlib use is unsupported while temporary global backend hooks are installed. Calls through this adapter are serialized; recursive capture fails explicitly rather than deadlocking. Every temporary hook is restored on all exits. The event recorder is capped by a caller-tightenable event limit and output size limit, not claimed to be an OS sandbox or to time-limit Figure.draw.

## Implementation slice

Architecture: `capture_pdf` in `plotproof/capture.py` returns an in-memory `CapturedPdf` (bytes/hash/DPI/save kwargs/origin/source inventory/events/issues). `plotproof/capture_events.py` holds immutable records and numeric conversion helpers. No changes to frozen B0 files or existing pure core evidence shapes. Importing the package root remains lightweight.

- [x] Write red tests for forced/unforced alpha, raw provenance, ordinary/constrained/plain/tight coordinates, actual native draw order, multiline one-source IDs, hidden text inventory, own-background identity and unassociated/raster emissions.
- [x] Implement a target-bound recorder: install temporary instance draw wrappers and PDF renderer hooks, accept only renderer.file.fh identical to the owned output buffer, capture before forwarding with no geometry mutation, and restore in reverse order.
- [x] Enforce supported runtime/save arguments, resource bounds, reentry/concurrency behavior, failed-save restoration and byte-identical rendering against an equivalent direct save (fixed metadata).
- [x] Independent read-only audit and owner regression/real-PDF checks. Save a new source-hash receipt; do not overwrite older core/I/O receipts.

Example contract:

```python
capture = capture_pdf(fig, bbox_inches='tight', pad_inches=0.1)
assert capture.capture_revision == 'CA1'
# Bytes still require read_pdf() page checks and a future manifest adapter.
assert capture.input_sha256 == hashlib.sha256(capture.pdf_bytes).hexdigest()
```

## Development record

Initial red run: 19 capture tests failed because the layer did not exist. After implementation, two tests exposed implementation issues: Text bbox patches do not carry a Figure pointer and were incorrectly attributed to the surrounding Text, and the per-request event cap was incorrectly reused as an inventory cap. The owner reproduced the first through actual event/source output, included registered background identities in target ownership, and separated the fixed inventory safety ceiling from the caller's event limit. The original 19 tests then passed; seven further controls covered nested foreign PDFs, serialized concurrent capture, table-cell enumeration, Annotation arrow exclusion, failure restoration and ambient tight settings.

The example `artifacts/b1/capture-ca1-example.pdf` and its JSON/PNG capture a real ordinary-layout tight save with a semitransparent rectangle. The owner rendered and viewed it. The example explicitly contains `collection_capture_pending` and `unassociated_material_event` (axis marker handling is not certified by this layer), so it is **not** a clean/checker verdict or a complete source-manifest demonstration. This limitation is preserved, not hidden to make the example appear ready.

Independent review found three additional problems, all reproduced by owner red tests: the TeX preflight used a narrower traversal than inventory and missed table-cell text; a saving-time callback could attach a Text bbox after initial registration; and a second capture on the same Figure checked its temporary PDF canvas before acquiring the serialization lock. Preflight now shares the explicit Cell traversal, Text registration rechecks background ownership on each draw, and mutable runtime/canvas/DPI checks occur inside the lock. Further owner tests require saving-time TeX activation to be rejected before any subprocess, and draw events to use current raw getter values rather than a stale inventory snapshot.

`SourceArtist` raw properties describe first registration; each `DrawEvent` raw properties describe the observed event. The applied GC factors remain separate. Changing source text/shape via arbitrary callbacks is not an assertion of complete source-manifest semantics; that adapter is still a separate milestone.

The first fixing pass had 31 capture/isolation tests passing. Scoped re-review then proved that title positioning/table auto-sizing can invoke TeX during text metrics before `Text.draw`, and that saving-time path effects or a Circle clip could evade one-time coverage checks. Owner red tests reproduced all five cases. The final design installs a target-aware `Text._get_layout` guard before even the first Agg draw, restores it with the other hooks, and reevaluates mutable raster/path-effect/clip state on every registration. No intercepted TeX process was allowed to run.

The owner observes **40 passing capture tests**, including separate-process PDFium raster checks of forced/unforced alpha and a tight crop retaining a figure-coordinate x=1.02 annotation. The last fixes are owner-verified, not presented as a new independent APPROVE verdict. The final full-suite command/result and tested-source hashes are recorded separately in `artifacts/b1/capture-verification.json`; refer to that receipt rather than infer a benchmark score from test counts. No old freeze or previous test receipt is changed by this development amendment.

## Self-review and boundary

The change affects measured capture operands, not the frozen D1–D4 decision thresholds, benchmark split, matching or metric gates. It necessarily requires a new prereg version before benchmark claims, because a corrected alpha operand can change a real result. An intermediate capture with empty issues is not enough to claim complete §2 enumeration, font provenance, high-confidence detection or full B1 completion. The next milestone explicitly owns those missing contracts.

## Assembly hook (2026-11-19)

`CapturedPdf.source_artists` now carries the registered `Text`/`Patch` objects in the
same order as `sources`. The field adds no captured fact, is not serialized, and exists
because assembly must pair a source ID with the exact object that produced it. A second
traversal of the figure is not equivalent: tick labels receive their text during draw,
and layout can register additional artists after the first inventory. The capture
revision, predicates, events and issues are unchanged.
