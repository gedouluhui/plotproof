## 1. Product claim and non-claims

**Claim.** For a Matplotlib `Figure` exported through PlotProof's wrapper in the same process, PlotProof compares the captured source text objects and geometry with the final single-page PDF, and reports evidence-backed findings, or `UNKNOWN` when the evidence is insufficient.

**Non-claims.**

- It is not a general PDF checker. It does not accept arbitrary PDFs in v1.
- It is not a semantic or aesthetic judge. It does not check whether a chart's message is true, whether a citation exists, or whether colors are attractive.
- It is not an ML model. The core is deterministic geometry and text evidence.
- It does not replace human review. `PASS` means "no supported defect found with sufficient coverage", not "the figure is correct".
- It does not claim real-world accuracy, user adoption, stars, or time savings before B2/B4 measurements exist.

## 2. Input contract

A v1 check consumes exactly one of these:

1. A live Matplotlib `Figure` plus the PDF written by `plotproof.export.save(fig, path)`, or
2. A frozen test bundle containing the captured source manifest (JSON) and the exported PDF, created by the same wrapper.

The wrapper must record: Matplotlib version, backend, `pdf.fonttype`, figure size in inches, DPI, save kwargs (`bbox_inches`, `pad_inches`, `transparent`, `pad_inches_effective`), the save bbox origin (§2 coordinate normalization), page size, cropbox, mediabox, rotation, output sha256, the figure bbox in display coordinates, and one entry for every render artist its deterministic traversal visits — every `Text` artist (including artists the §7.1 unit predicate excludes) and every filled artist (a filled patch or an image), in draw order. The traversal assigns each visited artist one integer index, its `source_object_id`; the index space is shared by `Text` and filled artists. A `Text` entry carries its index as the unit ID, text, font family list, resolved font files, font size in points, color, text alpha, artist alpha, facecolor alpha, rotation, its window extent in display coordinates (the source bbox), visibility, z-order, paint order, artist class, the explicit clip box in display coordinates (or `null`), `background_patch_id` (the index of its own background patch, or `null`), and, for a tick label, the tick location and the axis view limits; it also carries `is_unit` and, when it is false, the first failed §7.1 predicate term. A filled-artist entry carries its index as the occluder ID, `artist_class`, `path_kind` (`axis_aligned_rectangle`, `legend_frame`, `other_filled_path`, or `image`), `path_is_concave` (false for a rectangle or image), `fancybox` (for a legend frame, else `null`), facecolor alpha, artist alpha, paint order, the axis-aligned filled-path bounding box `R_a`, the filled area of the path (or `null` for an image), and `owner_unit_id` — the unit ID when the artist is that text's own background patch, else `null`. An image entry also carries its extent rectangle and image opacity (or `null`); its `R_a` is the extent rectangle. A filled path is concave when it has a hole or its flattened exterior boundary has a reflex interior angle; the wrapper records this classification from the path Matplotlib hands to the backend. The record also carries the warnings emitted during the save call and `source_units_total` — the number of `Text` entries whose `is_unit` is true; filled artists do not enter that count. Font size and the window extent are required by §7.1's height band and source bbox; paint order, `source_object_id`, alpha components, `R_a` and filled area are required by D2's occlusion evidence; `owner_unit_id` and `background_patch_id` are required by D2's own-background exclusion and D3's own-background demotion test; clip box, tick location, view limits and figure bbox are required by §7.1's unit predicate; `path_kind`, `path_is_concave`, image opacity and `fancybox` are required by D2's high-confidence geometry; `pad_inches_effective` is required by the tight-bbox transform; the warning list is required by D4's evidence (§4, §7.1); `source_units_total` is the independent count the detector's coverage must reconcile against (§7.1, §11). The benchmark binding pins `transparent=False`; a wrapper input with `transparent=True` is still a valid product input but is not a benchmark sample.

**Save warnings.** Warnings are captured with `warnings.catch_warnings(record=True)` around the `fig.savefig(...)` call only, and recorded as a deduplicated list of `{category, message}` pairs. Matplotlib emits a missing-glyph warning during both draw and save, so the same message can appear more than once; duplicates are collapsed by the exact `(category, message)` pair. Warnings emitted outside the save call are not recorded, so a warning cannot be attributed to a different export.

**Rejected as invalid input (ERROR):**

- multi-page PDF, page rotation ≠ 0, cropbox ≠ mediabox;
- encrypted or malformed PDF;
- a PDF not produced by the wrapper (missing source manifest or hash mismatch);
- a non-PDF export (`png`, `svg`, `eps`).

A figure whose only text is mathtext or path-only text is **not** `ERROR`: mathtext units are counted as unsupported and force `UNKNOWN`; path text is not a `Text` unit and is not counted; an empty unit set is `UNKNOWN` (§3.2, §4.1).

**Coordinate normalization.** All comparisons happen in PDF points with the origin at the bottom-left of the page. Matplotlib display coordinates also use a bottom-left origin. For a plain save (`bbox_inches` is `None`), convert both axes with `x_pt = x_display * 72 / dpi` and `y_pt = y_display * 72 / dpi`. For a tight save (`bbox_inches='tight'`), the page is a crop of the figure, so the same scale applies to a translated origin: the wrapper records `x0_px = (tight.x0 - pad_inches_effective) * dpi` and `y0_px = (tight.y0 - pad_inches_effective) * dpi`, and converts with `x_pt = (x_display - x0_px) * 72 / dpi` and `y_pt = (y_display - y0_px) * 72 / dpi`. No y-flip is applied in either case. The wrapper records the exact transform; no DPI is guessed from the PDF. If the transform cannot be established, the result is `UNKNOWN`.

The tight call is pinned: **before** the save, the wrapper calls `fig.canvas.draw()`, obtains `renderer = fig.canvas.get_renderer()`, computes `tight = fig.get_tightbbox(renderer)` (inches), resolves `pad_inches_effective` (`None` → `rcParams['savefig.pad_inches']`, measured 0.1), and only then calls `fig.savefig(path, bbox_inches='tight')` without further draws. Computing the bbox **after** the save is forbidden: measured on the 4×3 in probe figure, the post-save call returns a bbox that differs from what the save used (Δx0 −0.0047 in, Δy0 −0.0113 in, Δw +0.0047 in, Δh +0.0246 in), which moves the recorded origin and misaligns every box. The pre-save recipe reproduces the saved page exactly at both pads (predicted 282.0 × 210.0 pt at pad 0 and 296.4 × 224.4 pt at pad 0.1; actual identical).

Measured on this machine (Matplotlib 3.10.8, 4×3 in at 100 dpi, constrained layout, `pad_inches=0.1`): the recorded origin reproduces the saved page size exactly (predicted 296.4 × 224.4 pt, actual 296.4 × 224.4 pt); a horizontal y-label's source box aligns to its PDFium character union with IoU 0.745 under the translated transform and 0.268 under scale-only, while the plain-save control scores 0.745 under scale-only. The 0.268 is below the §7.1 0.50 threshold, so without the translation a legal tight-bbox export would be scored `low_overlap` and force `UNKNOWN`.

**Process rule.** Every PDFium call in a process is serialized. Parallel rendering is allowed only across separate processes. This is a hard requirement from the PDFium/pypdfium2 documentation, not an optimization. Object lifetimes are explicit (open → use → close in `try/finally`), and a render subprocess timeout kills only its own PID.

| Page geometry | rotation 0, cropbox == mediabox, finite size ≤ A2 |
| Text objects | title, suptitle, axis labels, tick labels, legend text, annotations (`Axes.text` / `annotate`), colorbar labels, `Figure.text` |
| Languages | English; Chinese (Simplified) when a CJK font is available; mixed CJK/English within one label |
| Text features | numbers, negative signs, units, thousands separators, multi-line text, opaque background bboxes; rotation 0 only in v1. Axis labels, shared axis labels, twin-axis labels, and colorbar labels are drawn horizontal in the benchmark (`rotation=0`) |
| Fonts | DejaVu Sans (bundled with Matplotlib) for ASCII; Noto Sans CJK SC or Source Han Sans SC (OFL) for CJK; user-provided fonts are allowed if the wrapper records the file |
| PDF text mode | `pdf.fonttype=42` fully supported; `pdf.fonttype=3` supported for ASCII only |
| Defect classes | D1 clipped text, D2 occluded text, D3 overlapping text, D4 missing glyph (see §4) |

### 3.2 Out of scope (not checked in v1)

An item in this list is outside the v1 evidence model. `PASS` is a statement about supported `Text` units only; it never means an out-of-scope item is correct. There are two distinct cases.

**Identifiable `Text` units that v1 does not check.** Nonzero-rotation text and mathtext are still `Text` objects, so they are enumerated as units with reason `unsupported_rotated` or `unsupported_mathtext`. They stay in the coverage denominator, are listed in `unknown_objects`, and force the sample to at least `UNKNOWN` (§4.1). They never become findings and are never silently dropped.

**Content that is not a supported `Text` unit.** v1 cannot enumerate it from the source manifest, so it is not counted and the report does not claim to have checked it:

- arbitrary PDFs, scanned PDFs, PDF/A, tagged-PDF semantics, optional content groups;
- multi-page documents (rejected as `ERROR` under §2), inset-axes geometry, table structure and rules, images containing text, 3D projection geometry;
- text rendered as vector paths with no `Text` object;
- RTL scripts, vertical text, Indic/Arabic shaping;
- color contrast, aesthetics, chart-message truth, citation truth;
- "label was removed and re-rendered" counterfactual detection (layout changes invalidate it);
- arbitrary PPTX/DOCX/HTML ingestion;
- remote fonts, network access, telemetry.

Table-cell strings and inset-axes or 3D text are ordinary `Text` objects: if they satisfy the §7.1 unit predicate they are checked as ordinary text; the table or axes structure itself is not checked.

A figure whose only text is mathtext has unsupported units and is `UNKNOWN`; a figure whose only text is path text has no units and is `UNKNOWN`. Neither is `ERROR`. A figure with **no units** is `UNKNOWN`, never `PASS`. A figure with any unsupported unit, or with text alignment coverage below 0.90, is also `UNKNOWN` (§4.1, §7.1).

### 3.3 Font policy

- Microsoft fonts (Microsoft YaHei, SimHei, SimSun) are **not** used in public benchmark artifacts and are never committed. The B0 feasibility run used Noto Sans CJK SC instead.
- The public CJK benchmark requires Noto Sans CJK SC (OFL-1.1) or Source Han Sans SC (OFL-1.1). The font binary is downloaded into `.fonts/` (git-ignored) and pinned by sha256 in the prereg. If the font is missing, affected CJK samples are `ERROR` with reason `font_unavailable`; they remain in the §8 recall, UNKNOWN, and ERROR denominators and are never silently skipped, dropped, or replaced by a proprietary font.
- DejaVu Sans is bundled with Matplotlib and is used for ASCII samples.
- Every sample records the resolved font family, file path, and file hash. Changing a font invalidates byte-level comparisons.

## 4. Defect classes and evidence levels

Only **high-confidence** findings may produce `FAIL`. Medium-confidence candidates produce `UNKNOWN` (manual review). Low-confidence candidates are not reported as defects.

### D1 — `clipped_text`

**Definition.** A supported, visible text object has glyph ink outside the visible page in the final PDF.

**Boundary predicate (defined once; §7 references it).** For a PDF character box `B = [x0, y0, x1, y1]` with positive area `A = (x1 − x0)(y1 − y0) > 0`, let `A_in` be the area of `B` intersected with the closed page rectangle `[0, W] × [0, H]`, and `A_out = A − A_in`. The box is **high-confidence boundary evidence** iff `A_out ≥ 0.5·A` or its center lies strictly outside the page (`cx < 0`, `cx > W`, `cy < 0`, or `cy > H`). It is **medium boundary evidence** iff `0 < A_out < 0.5·A` and its center is not strictly outside. A box with `A = 0` — a CR/LF character, a synthesized tick-separator space, or any degenerate box — is **ignored**: it is neither high nor medium evidence, contributes nothing to a union, and cannot make a text object clipped. The two sections must not restate this as a different area-inside fraction: the old phrasing "less than 50% of its area inside" and "at least 50% of the box area outside" disagree at `A = 0`, where the first is `0 < 0` (false) and the second is `0 ≥ 0` (true). PDFium returns zero-area boxes for the CR and LF of a line break and for the spaces that separate x tick labels (measured: 2 of 125 characters on a title-only fixture, 21 of 180 on an axes with six x tick labels and a title, §13); spaces inside ordinary text instead carry a hairline positive-area box (measured ≈0.01 pt tall at the pinned 10 pt binding; §14), which the area test handles without a special case.

**High-confidence evidence.**

- At least one aligned PDF character box is high-confidence boundary evidence under the predicate above; and
- the source object is visible and its alignment is unique under §7.1 (assigned a span and not removed as ambiguous).

`in_layout=False` is **not** an exclusion: the text is still drawn, so it is still checked.

**Medium / UNKNOWN.** At least one aligned character box is medium boundary evidence (for example, a box 2 pt outside with 90% of its area inside). Inputs whose page geometry is unsupported are rejected as `ERROR` by §2 and never reach D1.

**Legal counterexamples.** Text outside the axes patch but inside the page; text within 1 pt of the edge but fully inside; text hidden by `visible=False` (recorded per §2 with `is_unit = false` and first failed term `invisible`, excluded from the unit set, not a defect); `bbox_inches='tight'` expanding the page to include an annotation; a fully inside multi-line text whose line breaks and tick-separator spaces produce zero-area PDFium boxes. The last case is executable: `spikes/b0_d1_boundary_probe.py` requires zero high and zero medium evidence on all three pinned fixtures, while the literal r8 §7 inequality flags every zero-area box on the same pages (2, 21 and 2 respectively).

### D2 — `occluded_text`

**Definition.** An opaque artist painted after a supported text object covers the text's painted character boxes enough that the text cannot be read in the final render.

**High-confidence evidence.**

- The text object is visible, rotation 0, and aligned under §7.1; at least one aligned character box exists;
- one filled artist with effective alpha `α_eff ≥ 0.95` (defined below) has an effective paint order **after** the text object;
- its filled path's axis-aligned bounding box `R_a` (the operand defined under joint coverage) covers ≥ 90% of the union of the text object's aligned character boxes `T`, not merely ≥ 90% of the source bounding box;
- its geometry lies inside the page: `R_a` is inside `[0, W] × [0, H]`; for a filled path this is conservative because the path lies inside its bbox;
- supported occluder geometry is one of: `path_kind = "axis_aligned_rectangle"`; `path_kind = "legend_frame"` with `fancybox=false`; `path_kind = "other_filled_path"` with `path_is_concave=false` and recorded filled area ≥ 95% of `R_a`; or `path_kind = "image"` with a recorded image opacity (the alpha test below applies to images as well). A rounded legend frame, a concave path, a path whose filled area is below 95% of `R_a`, or an image without a recorded opacity is at most medium;
- the text's characters are present in the PDF text extraction, proving the text object was emitted (this is **not** evidence that glyph ink is visible; it only excludes skipped objects); and
- the occluder's `owner_unit_id` is not this text's unit ID, and it is not painted before the text.

**Effective paint order.** The wrapper records the actual draw order during the save by wrapping each artist's `draw` call and appending the artist to an ordered list; it does not infer order from `zorder` alone. Ties and figure/axes interleaving use the recorded sequence. If paint order cannot be recorded, any occlusion claim is demoted to medium.

**Effective alpha.** For a filled patch, `α_eff = facecolor alpha × artist alpha`, both taken from the wrapper record; for an image occluder, `α_eff = recorded image opacity × artist alpha`. The product, not either factor alone, decides opacity: a facecolor alpha of 0.50 under a fully opaque artist is semi-transparent paint (`α_eff = 0.50`), and an artist alpha of 0.50 over an opaque facecolor is the same. A fill is opaque only when `α_eff ≥ 0.95`; it is semi-transparent when `0.50 ≤ α_eff < 0.95` and can support at most medium evidence; below 0.50 it is excluded from occlusion evidence and cannot make text unreadable. If an image's opacity is not recorded, the occluder is at most medium. Both factors are recorded in `evidence` so the product is recomputable (§11).

**Joint coverage.** The **contributing artists** of a text object are the filled artists whose `α_eff ≥ 0.50` (an image needs a recorded opacity ≥ 0.50), whose `owner_unit_id` is not this text's unit ID, whose `R_a` intersects `T` with positive area, and whose recorded paint order is after the text object. The text's own background patch is never a contributing artist, and an artist below 0.50 is excluded from occlusion evidence. If paint order cannot be recorded, every otherwise-contributing artist is treated as contributing and any finding is at most medium. For the character union `T` and contributing artists `a` with axis-aligned filled-path bounding boxes `R_a` (an image uses its extent rectangle), the joint coverage is `c = area(∪_a (T ∩ R_a)) / area(T)`. Overlapping artists are counted once: two artists that each cover 60% of the same text yield `c = 0.60`, not 1.20. §7 reports the aligned character boxes of `T`, every `R_a`, every intersection box `T ∩ R_a`, and each artist's own coverage of `T`, from which `c` and the contributing set are recomputable.

**Medium / UNKNOWN.** Joint coverage `0.50 ≤ c < 0.90` by the contributing artists; `c ≥ 0.90` where no single contributing artist alone reaches 0.90; a contributing artist with `α_eff` in `[0.50, 0.95)` or an unrecorded image opacity; a candidate that meets the coverage and alpha thresholds but fails a high-only geometry test — a rounded legend frame, a concave path, a filled area below 95% of `R_a`, or `R_a` not inside the page; paint order not recorded or ambiguous. High confidence takes precedence when both the high and a medium description fit.

**Legal counterexamples.** A text bbox background painted **behind** the text (lower paint order); a legend frame covering data points but no supported text; `frameon=False`; a semi-transparent frame over text (→ `UNKNOWN`, not `FAIL`).

### D3 — `overlapping_text`

**Definition.** Two distinct supported text objects have painted regions that overlap enough to impair reading.

**Operands and ratio.** For a pair in which both units are aligned, the operands are the unions of the two units' aligned character boxes, `U_1` and `U_2`, and the ratio is `r = area(U_1 ∩ U_2) / min(area(U_1), area(U_2))`. For a pair in which at least one unit cannot be aligned, the operands are the two source bboxes transformed into PDF points, `B_1` and `B_2`, with the same formula; this operand set is capped at medium and never produces a high-confidence finding. If the smaller operand has zero area, no D3 finding is emitted for the pair because `r` is undefined.

**Own background patch.** An object's own background patch is the filled artist whose `owner_unit_id` is that unit's ID (§2), equivalently the artist named by the unit's `background_patch_id`. When its `α_eff = facecolor alpha × artist alpha ≥ 0.95` and its recorded `R_a` intersects the overlap region with positive area, a pair at `r ≥ 0.50` is **demoted to medium, not suppressed**: for a concave patch this bbox test is conservative, so an intersecting bbox cannot prove that the patch actually covers the overlap, and the patch's own paint order is not used to promote or suppress a case.

**High-confidence evidence.**

- Both objects are visible and aligned; neither object's own opaque background patch intersects the overlap region with positive area;
- `r ≥ 0.50` on their aligned character-box unions; and
- at least one positive-area aligned character box from each object overlaps the other by ≥ 0.5 pt in both axes.

**Medium / UNKNOWN.**

- Aligned pairs with `0.15 ≤ r < 0.50`.
- Aligned pairs with `r ≥ 0.50` that fail a high-only guard: no positive-area character-box pair from the two objects overlaps by ≥ 0.5 pt in both axes, or an own opaque background patch intersects the overlap region with positive area. These guards choose between high and medium; they never turn a pair at `r ≥ 0.50` into no finding.
- For a pair in which at least one unit cannot be aligned, any `r ≥ 0.15` on the source bboxes is medium regardless of how large `r` is; below 0.15 no finding is emitted.

High confidence takes precedence when both the high and a medium description fit. Rotated text is out of scope (§3.2), not a medium D3 finding. Lines within one multi-line text object are not a pair and do not force `UNKNOWN`; the object remains supported for D1/D2/D4.

**Legal counterexamples.** Bounding boxes touch but rendered ink does not overlap; multi-line lines inside one text object; a text object's own background patch painted behind its own text where no other object's character boxes fall inside the patch. Rotated labels with separated ink must be `UNKNOWN`, never `FAIL`, because rotated text is outside v1 scope.

**Class precedence and collateral findings.** D3 is only between two distinct text objects; D2 is text versus an opaque artist. When two rules fire on the same object, the report keeps the highest-precedence class in the order `D1 > D4 > D2 > D3` and records the suppressed class as an evidence note. Suppression is **confidence-scoped**: a finding suppresses only findings of the same confidence. A medium-confidence finding never suppresses a high-confidence finding, and a high-confidence finding never suppresses a medium one; both are reported, and the aggregate state follows §4.1, so a high-confidence finding left in place still produces `FAIL`. For D3, a pair at confidence `c` fires on its members at confidence `c`: the pair at `c` is suppressed as a whole only by a higher-precedence finding at the same confidence `c` on either member. A higher-precedence finding at the other confidence leaves the pair intact and both findings are reported. A suppressed D3 pair is dropped as a whole, because its ratio is a property of the pair; baseline B applies the same rule at its single, high confidence level (§9). A single injected mutation must not produce a second high-confidence finding on the same sample; if a collateral defect is found during label review, the sample is either regenerated or all instances are labeled and the sample enters a multi-defect subset with every reference recorded. Such a sample is excluded from the single-instance counts in §5 and reported separately.

### D4 — `missing_glyph`

**Definition.** A character intended to be rendered has no usable glyph: every font in the resolved stack either omits the code point from its Unicode cmap or maps it to glyph ID 0, and the save emitted a missing-glyph warning for it. The visible result is `.notdef` (tofu) or a blank cell; the evidence is the cmap/glyph-ID state plus the warning, not the pixels (§4's extraction note).

**High-confidence evidence.**

- Every font in the resolved font stack that Matplotlib actually used for that text object (fontTools, Unicode cmap tables) either omits the code point from its Unicode cmap or maps it to glyph ID 0; no font in the stack maps it to a non-zero glyph ID, so no fallback supplies it; and
- the wrapper's recorded warnings (§2) contain a missing-glyph warning, captured during the same `fig.savefig` call that wrote the checked PDF, whose message names that character's code point and at least one font family of the resolved stack for this object; and
- the source text object is visible and aligned under §7.1 (using the missing-glyph alignment rule for its remaining characters).

If the wrapper cannot resolve which font file was used for the object, the case is at most medium even when a warning exists.

**Warning attribution.** The warning list is scoped to one save, so it can only support objects of that sample. Attribution to an object additionally requires the object's own text to contain the named character. A warning emitted outside the save call, or a bundle without a recorded warning list, cannot support a high-confidence D4 finding. If two or more supported units contain the same missing character, either every such unit is labeled (the sample enters the multi-defect subset and is excluded from the single-instance counts, §4 precedence rule, §5) or the sample is regenerated; the D4-injection rule in §5 requires the injected character to occur in exactly one unit.

**Medium / UNKNOWN.** cmap absent or glyph ID 0 in every font but no warning; warning present but the resolved font stack cannot be verified; the warning names a font not in the resolved stack; a fallback font may or may not have supplied the glyph; the stack disagrees (some fonts omit the code point or map it to glyph ID 0, another maps it to a non-zero glyph); Type 3 text without Unicode mapping; the font test and the naming warning hold, but the unit has no unique alignment under §7.1 even after the missing-glyph procedure (for example, deleting the proven-missing characters empties its canonical string, or the second search yields no uniquely assigned span). That last case is a reported medium finding carrying the transformed source bbox as its evidence; it must never be dropped as `no_text_match`, so a visible text unit whose glyph these two tests prove missing can never leave the sample `PASS`.

Mathtext is not a D4 case: it is an unsupported unit recorded in `unknown_objects` as `unsupported_mathtext` (§3.2), never a finding. Path text is not a `Text` unit at all (§3.2), so it is neither a unit nor a finding.

**Explicitly not evidence.** PDF text extraction containing the character does **not** prove the glyph rendered. The B0 spike rendered U+9F98 with DejaVu Sans, emitted a missing-glyph warning, and PDFium still extracted U+9F98. Extraction presence must not turn a tofu into `PASS`. The reverse also holds: under `pdf.fonttype=42`, U+20000 is absent from extraction **and** from both benchmark fonts, and the warning is the evidence (measured), so extraction absence is not by itself rendering evidence either; the cmap check and the saved-warning attribution carry the finding.

**Legal counterexample.** A fallback font in the family list supplies the glyph: no warning is emitted (verified), so the sample is `PASS`.

### 4.1 Sample state aggregation

Priority is fixed:

```
ERROR > FAIL > UNKNOWN > PASS
```

- `ERROR`: invalid input, hash mismatch, renderer crash, timeout, internal error, a required font unavailable (`font_unavailable`), or a report whose `aligned_units + unaligned_units + unsupported_units` does not equal the wrapper's `source_units_total` (`unit_accounting_mismatch`).
- `FAIL`: at least one high-confidence finding.
- `UNKNOWN`: no high-confidence finding, but at least one medium finding, at least one unsupported unit (`unsupported_rotated` or `unsupported_mathtext`), text alignment coverage below 0.90, or an empty unit set.
- `PASS`: no findings, no unsupported units, and text alignment coverage ≥ 0.90. Non-`Text` out-of-scope content may exist but is never claimed checked (§3.2).

A medium finding never becomes `FAIL`. A `FAIL` may coexist with unknown objects in the JSON; the aggregate state is `FAIL`, but the report must still list the unknown objects and coverage. A sample with zero text units is `UNKNOWN` even if no rule fired.

Three templates carry a scope note in the manifest and bind the generator; the validator enforces each binding structurally:

- **D11 (log scale)** must render log tick labels as plain text through the callable `FuncFormatter('{:g}'.format)`. - **D12 (datetime axis)** uses horizontal date tick labels. Rotated date ticks are out of scope and would push the clean sample below the 0.90 coverage gate; the validator requires `date_ticks_horizontal` plus a scope note for any `date_ticks_*` feature and rejects any template feature containing `rotated`.
- **H09 (scientific notation)** must render a plain offset text (`1e3`) with `axes.formatter.use_mathtext = False`. A `$`-bearing offset is unsupported (§3.2) and may not be the target role; the validator requires the exact `ScalarFormatter(useMathText=False)` binding and a scope note.

**D4 injection rule.** Every `missing_glyph` variant injects exactly one character that is absent from every font in the resolved stack: U+20000, verified absent from both DejaVu Sans and Noto Sans CJK SC. Under `pdf.fonttype=42` that character disappears from PDF text extraction, which is the harder alignment case; §7.1's missing-glyph rule matches the remaining characters (measured: span-vs-source-bbox IoU 0.773 (0.7734 centered, 0.7730 left-aligned) for the unit `Trend 𠀀 chart` drawn in DejaVu Sans at 10 pt, above the 0.50 threshold; `spikes/b0_missing_glyph_alignment_probe.py`, `artifacts/b0/missing-glyph-alignment-probe.json`, round 12). The round-7 prose example `Trend 鿘 chart` contains U+9FD8, a different character, and its 0.7045 is not a U+20000 measurement. U+9F98 must not be used: the B0 spike observed it in the extracted text despite the warning, so it exercises the easier case. The generator must place the character inside the target text, prove it occurs in exactly one unit of the sample, and re-run the collateral-defect and page-clipping checks of this section. Under `pdf.fonttype=3` the minus sign and CJK text are also dropped from extraction (§0), which is why the binding pins type 42.

**Horizontal label binding.** Every template whose features contain a y-axis label (`ylabel`, `shared_ylabel`, `two_ylabels`, `ylabel_en_unit`, `ylabel_cjk_unit`) or `colorbar_label` must also declare `labels_horizontal`; the validator rejects a label-bearing template without it. The manifest's `label_binding` object fixes the rest: all templates use Matplotlib's constrained layout (`layout="constrained"`), axis labels use `rotation=0` with `labelpad=4.0` (the 3.10.8 default, pinned explicitly so an rcParam change cannot move the geometry), and the two colorbar templates (D08, H04) declare `colorbar_horizontal` and use a horizontal colorbar whose label is the colorbar axes' x-label at `rotation=0`. Rotation alone is not sufficient: with the default alignment the label's box is centred on an anchor that Matplotlib places just left of the tick labels, so half of the box lies over them. The binding therefore also fixes alignment: left-side axis y-labels use `ha='right'`, right-side and twin-axis y-labels use `ha='left'`, and a figure-level shared y-label (`Figure.supylabel`, H11) uses `ha='left'` with constrained layout's autoposition, which reserves its width as a left margin. Measured on a 4 × 3 in probe figure (400 × 300 px at 100 dpi; the binding is applied to every benchmark template at the pinned 10 × 6 in, where the generator's clean check is the certifying measurement): before the alignment binding, a left y-label (`Value (USD)`, ticks 0/4/8/12/16) covered the worst tick label's box at 0.214 smaller-box ratio, a twin-axis right y-label (`Right value`) at 0.607 (on the round-6 source-bbox measure this would have been a high-confidence D3 `FAIL`), and a figure-level shared label ran off the page (bbox x0 = −54.458 px); after it, every label-to-tick ratio is 0.000 and every label box is inside the page (shared label 4.167–121.417 px, axes left 148.223 px). These round-6 numbers are source-bbox ratios and are retained as historical record; the §4 D3 rule measures aligned pairs on aligned character-box unions, so neither number is by itself v1 high-confidence evidence, and the generator's executable clean check is the certifying measurement at the pinned size. Constrained layout is required because a horizontal y-label is wider than a rotated one: without it the label is pushed off the left page edge at the default margin (measured: bbox x0 = −10.5 px on a 400 px page). A horizontal label on a *vertical* colorbar is also rejected because a long label is centred on the bar's right side and overlaps its tick labels regardless of labelpad (measured: 74 px² overlap with a 20 pt pad for a 139 px-wide label); a horizontal colorbar keeps the label below the bar, inside the page and clear of the tick labels for label widths from 10 to 139 px. Every counterexample except L04 must also declare `labels_horizontal`. This binding is what makes the clean and counterexample `PASS` states reachable under the rotation-0 scope; a default vertical ylabel would be an unsupported unit and force `UNKNOWN` (§3.2, §4.1). Before sealing, the generator applies the manifest check `no page clipping and no D3 candidate with smaller-union coverage >= 0.15` to every clean sample; a sample that fails is regenerated, never relabeled. The 0.15 threshold is the lower edge of D3's medium band (§4), so any pair at or above it would make the sample at best `UNKNOWN`.

**Generator labels are not ground truth.** The mutation script produces traceable labels (a known object and a known injection), but every holdout sample must be reviewed once against the exported PDF before sealing. If only one person reviews, the project must not claim double annotation or inter-annotator agreement.

**Legal counterexamples.** L01–L12 cover white label backgrounds, legends over data but not text, touching bboxes with separated ink, rotated bbox overlap with separated ink (expected `UNKNOWN`, not `FAIL`, because rotated text is out of scope), legal near-edge text, a semi-transparent frame over text (expected `UNKNOWN`), white labels on a heatmap, frameless legend over data, a colorbar label near but not overlapping ticks, an axis label outside the axes but inside the page, tight-bbox expansion, and multi-line line spacing. Every counterexample except L04 draws its axis and colorbar labels horizontally with the same alignment binding, so L09 and L10 remain `PASS`-reachable; L04 is the only counterexample with intentional rotated text.

## 6. Holdout protocol (frozen before detector development)

1. **Family split.** The split is by template family (template ID), never by sample. Dev and holdout are fixed in the manifest. Similarity groups (e.g. line charts on both sides) are recorded; the holdout is not claimed to be statistically independent.
2. **Generation and seal.** Dev samples may be generated and inspected freely at B1. Holdout samples are generated at B2 by a separate generation script (`benchmark/generate_holdout.py`, created at B2) in a separate process and written to `benchmark/holdout/` (git-ignored). **Before generation, the detector code, every threshold, and the evaluation script are frozen and tagged**; that revision is recorded in the seal. The committed `benchmark/holdout/seal.json` records each sample's sha256 and size, the generator script hash, the frozen detector and evaluation revisions, the label-review log hash, and the generation environment; it does **not** contain labels. Labels live in `benchmark/holdout/labels.json` (git-ignored) and their sha256 is recorded in the seal.
3. **No tuning on holdout.** No parameter selection, rule threshold, prompt, or code change may use holdout outputs or labels. The dev set is the only development signal. Because the detector is frozen before the label-review session of item 5, a label correction cannot feed back into detector code for this prereg version.
4. **One unseal per prereg version.** At B3, before running the evaluation, the seal is verified, the frozen detector and evaluation-script revisions are checked against the seal, and the unsealing is logged with a UTC timestamp. The holdout is then run once.
5. **Label review and corrections.** Before sealing, the project owner acts as the **label reviewer**: they open the holdout PDFs and the machine-generated candidate labels in one logged session, solely to correct a wrong expected state or target unit. Every correction is recorded in `benchmark/holdout/label_review_log.json` (git-ignored) as sample ID, old label hash → new label hash, reason code, and UTC timestamp; the log hash goes into the seal and the log contains no label text. The reviewer must not run the detector on holdout inputs during this session. This session is the **only** permitted pre-seal opening of holdout files; opening them at any other time burns the holdout under item 6. After sealing, a label change requires a new prereg version and a full rerun. No sample may be moved to "unsupported" after seeing results.
6. **Accidental inspection burns the holdout.** Any opening of a holdout sample or label file outside the logged label-review session of item 5, or any detector run on a holdout input before the B3 unseal, burns the holdout: it is moved to dev-only use, a new seed/template set is generated, and a new prereg version is written. The project must report the burn. Filesystem auditing is not available, so this remains a procedural rule; the label-review log and the seal are the only recorded evidence.
7. **Crash and partial-run rule.** A run that crashes before writing any predictions file may be rerun once with the same seal; the crash, timestamp, and environment are logged. Once a predictions file exists, a rerun requires a new prereg version and the first result stands.
8. **Custodian limitation.** For v1 the project owner is the only custodian, the label reviewer, and the detector author. The seal is a procedural commitment verified by hashes and timestamps, not access control; no independent custodian exists. The limited claim is: the detector revision was frozen before the label-review session, no detector run touched holdout inputs before the B3 unseal, and the label-review log and correction hashes are recorded. It is **not** a claim of blindness or independent annotation. Results must say so.
9. **No independence overclaim.** Synthetic templates, shared fonts, and shared code mean the holdout measures generalization across templates, not across the real world. Report this limitation with every result.

## 7. Evaluation units, matching, and deduplication

**Reference defect instance.** A tuple `(sample_id, defect_class, source_object_id, related_source_object_id)`. `source_object_id` is the unit ID defined in §7.1: the wrapper's deterministic artist-traversal index, recorded for every `Text` object. For D3 the instance is a pair of units and `related_source_object_id` is the other unit; the pair is unordered and normalized to `(min, max)` at construction, so `(a, b)` and `(b, a)` are one instance. For D1, D2 and D4, `related_source_object_id` is `null`. A sample may contain more than one instance; v1 generators inject one.

**Finding.** A JSON object with at least: `sample_id`, `defect_class`, `rule_id`, `source_object_id` (nullable), `related_source_object_id` (nullable; required for D3 and `null` otherwise), `confidence` (`high`/`medium`), `state` (`FAIL`/`UNKNOWN`), `page`, `box_pdf_points`, `source_text`, `evidence`, `renderer_version`, `input_sha256`.

**`box_pdf_points` by class.** The box is a PDF-point rectangle `[x0, y0, x1, y1]` with a bottom-left origin, unrounded; rounding happens only for display and the duplicate key. It is defined per class so two implementations cannot report different boxes for the same evidence:

- **D1 `clipped_text`:** for high evidence, the bounding rectangle of the union of the aligned character boxes that are high-confidence boundary evidence under §4's predicate. For medium evidence, the bounding rectangle of the union of the aligned character boxes that are medium boundary evidence. Zero-area boxes are never included, because §4 ignores them. The box may extend beyond the page; it is not clipped for reporting.
- **D2 `occluded_text`:** let `T` be the union of the aligned character boxes the coverage was computed over. For each contributing artist `a`, let `R_a` be its axis-aligned filled-path bounding box (for an image occluder, its extent rectangle). The finding box is the bounding rectangle of `∪_a (T ∩ R_a)`. For one artist this is the intersection's bounding rectangle; for joint coverage it is the bounding rectangle over every contributing intersection. The finding's `evidence.occluders` lists every `a` with its `source_object_id`, its `R_a`, the intersection boxes `T ∩ R_a`, and its own coverage of `T`; `evidence.character_boxes` lists the aligned character boxes of `T`. The joint coverage and the box are recomputable from these operands. An image occluder uses its own `source_object_id` from the same traversal, not `null`.
- **D3 `overlapping_text`:** when both units are aligned, the bounding rectangle of the intersection of the two aligned character-box unions `U_1` and `U_2`, with `evidence.operand_set = "char_unions"`. For the unaligned medium case (§4 D3), the bounding rectangle of the intersection of the two transformed source bboxes, with `evidence.operand_set = "source_bboxes"`. The finding's `source_object_id` is the smaller unit ID and `related_source_object_id` the larger. `evidence` also records, for `char_unions`, the character-box pair that meets the high-only 0.5 pt overlap rule or the fact that none does, and, when an own background patch was tested, its `owner_unit_id` and `R_a`.
- **D4 `missing_glyph`:** the unit's transformed source bbox, which contains the region the missing character was laid out in. `evidence.source_bbox_pdf_points` records that bbox, so the reported box is recomputable without rerunning the detector.

**Matching.**

- A finding matches a reference if they share `sample_id` and `defect_class` and either (a) for D3, both `source_object_id` and `related_source_object_id` equal the reference's after the same `(min, max)` normalization — a D3 finding missing either ID matches nothing; or (b) for D1/D2/D4, `related_source_object_id` is `null` on both sides and either the `source_object_id` is equal, or the finding has no source ID and the IoU of its box and the reference instance's source-object box, transformed to PDF points under §2, is ≥ 0.50.
- One finding matches at most one reference; choose the highest IoU. One reference is matched by at most one finding.
- A reference with no matching finding is a miss, even if the sample state is `UNKNOWN` or `ERROR`. Misses stay in the recall denominator.
- Findings on objects declared out of scope before the run are reported separately and excluded from precision/recall denominators. Adding an object to "out of scope" after seeing results is forbidden.
- Duplicate findings for the same reference count as one TP; any extra non-identical finding for that reference is a false positive. Byte-identical duplicates are collapsed by the key `(sample_id, defect_class, source_object_id, related_source_object_id, rule_id, box rounded to 0.1 pt)`. Because the D3 pair is normalized, the two orders of one pair collapse to one key.
- A finding with `confidence=medium` is not a TP or FP for precision; it forces the sample to at least `UNKNOWN` if no high-confidence finding exists.

**Precision denominator.** All high-confidence findings on supported objects in the holdout, including findings on clean samples and counterexamples. If the denominator is zero, precision is **undefined and the gate fails** (a silent detector cannot pass by returning nothing).

**Recall denominator.** All reference defect instances in the preregistered supported holdout (96). `UNKNOWN`/`ERROR` misses stay in the denominator. A conditional recall on the decidable subset may be reported separately, but never used for the release gate.

### 7.1 Source-to-PDF text alignment

Alignment runs once per sample, before any defect rule. It maps each supported **source unit** to PDF character boxes. D1, D2, D4, the coverage metric and D3's ordinary path use only aligned units, so this procedure is part of the contract, not an implementation detail. Two explicit medium exceptions do not need alignment — D3's source-bbox case when at least one member cannot be aligned, and D4's proven-missing unit with no unique alignment after the missing-glyph procedure — and "Use of evidence" below bounds them.

**Unit.** A Matplotlib `Text` object (including `Annotation`, tick labels, offset text, legend labels, colorbar labels, `Figure.text`, and table-cell text) is a **unit** when all of these terms hold, evaluated in this order:

1. `text_nonempty`: `get_text().strip()` is non-empty.
2. `alpha_positive`: text alpha > 0 and artist alpha > 0.
3. `visible`: `get_visible()` is true.
4. `extent_nonempty`: its window extent `W` in display coordinates has width > 0 and height > 0.
5. `intersects_figure`: `W` intersects the figure bbox with positive area.
6. `not_fully_clipped`: its effective clip box `C` is `null`, or `area(W ∩ C) > 0`. `C` is `null` when `clip_on` is false; otherwise it is the clip box after an identical draw.
7. `tick_in_view` (tick labels only): its tick location `t` satisfies `min(axis view limits) ≤ t ≤ max(axis view limits)`, so boundary values and inverted axes are included.

The first term that fails is recorded by its name, one of `empty_text`, `alpha_nonpositive`, `invisible`, `empty_extent`, `outside_figure`, `fully_clipped`, `tick_outside_view`. The wrapper records every visited `Text` artist with these predicate terms and its own `is_unit` verdict (§2); the detector recomputes the predicate from the recorded terms, and a disagreement is `ERROR` (`unit_accounting_mismatch`). A multi-line string is one unit; Matplotlib draws its lines inside one artist draw call, and its characters are contiguous in content order. A unit is **supported** when its rotation is exactly 0.0° at draw time and its text contains no `$`; otherwise it is **unsupported**, with reason `unsupported_rotated` or `unsupported_mathtext`. Unsupported units are listed in `unknown_objects`, stay in the coverage denominator, and force the sample to at least `UNKNOWN` (§4.1). Unit ID is the deterministic artist-traversal index recorded by the wrapper; it is the `source_object_id` used by findings and reference instances (§7). A filled artist keeps the same index space as its occluder ID, but it is not a unit and does not enter `source_units_total`.

**Canonical form.** Source side: strip the unit's text (remove leading and trailing whitespace), then map every Unicode whitespace character to U+0020; collapse each maximal run of whitespace to one U+0020; then, per character `c` of the collapsed string, replace `c` with `NFKC(c)` only when `NFKC(c)` is exactly one character — when the normalization expands `c` to two or more characters (for example U+FB01 `ﬁ` → `fi`), keep `c` unchanged. The PDF side applies the same map/collapse/NFKC steps without the strip. NFKC is applied character by character on the collapsed string, never to the string as a whole, so a compatibility expansion cannot change the character count or shift canonical indices. No case folding, no deletion of non-whitespace characters, no ligature expansion. Record for every retained source character the canonical index it maps to, and for every PDF character the canonical index it maps to; characters removed by the source strip have no canonical index, and characters inside one collapsed whitespace run share one canonical index. After stripping, a source unit's canonical string neither starts nor ends with a space. The PDF side is not stripped; because `S` starts and ends with a non-space, PDF leading or trailing spaces cannot form part of a candidate match. The collapse is required because PDFium returns a line break as CRLF: the source newline produces one canonical space, and the two PDF characters produce one as well.

**Candidates.** Let `S` be the unit's canonical string and `L = len(S)`. For every position `p` where the PDF canonical string satisfies `pdf_canon[p:p+L] == S`, let `i` be the PDF character whose canonical index is `p`, and `j` one past the PDF character whose canonical index is `p+L-1`. Both are unique because `S` starts and ends with a non-space. The candidate span `[i, j)` includes every PDF character whose canonical index falls in `[p, p+L)`, including CR/LF characters inside a collapsed run. A candidate is valid only if:

- its span bbox (union of the char boxes) has `IoU ≥ 0.50` with the unit's source bbox transformed into PDF points (§2); and
- the median height of the span's char boxes with positive height, divided by the font size in points, is in `[0.20, 1.50]`. A span with no positive-height char box is invalid.

**Missing-glyph alignment.** Some missing characters are dropped from the PDF text stream entirely (measured: U+20000 under `pdf.fonttype=42`), so the exact canonical string can never be found and the unit would be unaligned with `no_text_match`, capping D4 recall at zero. For a unit whose text contains a character that the same save's recorded warnings prove missing — a missing-glyph warning naming that code point, plus the §4 D4 glyph test in every resolved font of the unit (the code point is absent from that font's Unicode cmap or maps to glyph ID 0) — alignment therefore runs a second candidate search. Let `T` be the unit's text with every such proven-missing character deleted; strip `T` and recompute its §7.1 canonical string (the whitespace collapse runs again, so `Trend`, space, [deleted], space, `chart` becomes `Trend chart`). Search that string in the same PDF canonical string and accept a candidate on the same height band, but require `IoU ≥ 0.50` against the unit's **full** source bbox, which still contains the missing character's layout region. The second search runs only when at least one character was deleted; otherwise it is skipped. Its valid candidates enter the same assignment as ordinary candidates, and the unaligned reason is computed over the union of both searches: `no_text_match` if neither `S` nor `T` occurs, `height_mismatch` if occurrences exist but none satisfies the band, and `low_overlap` if the band passes but none reaches IoU 0.50. If `T` is empty after stripping, the unit is unaligned with `no_text_match`; when the §4 D4 font test and naming warning still hold for that unit, the unaligned unit is a medium D4 finding (§4 D4), not a silent drop. Measured: for the unit `Trend 𠀀 chart` drawn in DejaVu Sans at 10 pt, the PDF span for `Trend chart` scores IoU 0.773 against the full source bbox (0.7734 with centered text, 0.7730 with left-aligned text), above the threshold (`spikes/b0_missing_glyph_alignment_probe.py`, `artifacts/b0/missing-glyph-alignment-probe.json`, round 12). This rule applies only to characters proven missing by §4's evidence; a typo, a changed word, or an unsupported font substitution is not covered, and a unit whose remaining text does not match the PDF stays `no_text_match`.

**Reason precedence.** A unit with no valid candidate is unaligned with exactly one reason: `no_text_match` if no span has the same canonical text; `height_mismatch` if equal-text spans exist but none satisfies the height band; `low_overlap` if equal-text spans satisfy the height band but none reaches IoU 0.50. A unit that has valid candidates but loses every one of them in assignment is `conflict`.

**Assignment.** Sort all valid `(unit, span)` pairs by `(IoU descending, unit ID ascending, span start ascending)` and assign greedily; a pair is accepted only if neither the unit nor the span is already assigned. One unit maps to at most one span, one span to at most one unit. This is deterministic and does not depend on iteration order of dictionaries.

**Ambiguity.** A unit is unaligned with reason `ambiguous` if, after assignment, either:

- another span with the same canonical text — assigned or not — has all four bbox edges within 1.0 pt of its assigned span (two indistinguishable instances at the same place); or
- its two best valid candidates have bbox centers within 2.0 pt of each other and IoU values differing by less than 0.02 (geometry cannot break the tie).

Ambiguous units are removed from the assignment and count as unaligned. Their assigned spans are removed with them and are not reassigned; no second pass runs. This is conservative: an ambiguity can only lower coverage.

**Unique.** A unit's alignment is **unique** when the assignment gives it a span and it is not removed as ambiguous. An unaligned unit, an ambiguous unit and an unsupported unit therefore never have a unique alignment, which is why D1's high-confidence condition (§4) requires uniqueness: unaligned, ambiguous or unsupported text cannot support a high-confidence D1 finding.

**Unaligned reasons.** `no_text_match`, `height_mismatch`, `low_overlap`, `ambiguous`, `conflict`, `unsupported_rotated`, `unsupported_mathtext`. Each is recorded with the unit ID in `unknown_objects`.

**Coverage.** `source_units_total` is the number of units enumerated by the wrapper's deterministic traversal, recorded in the source manifest independently of the detector. For one sample, `units_accounted = aligned_units + unaligned_units + unsupported_units` must equal `source_units_total`; a mismatch is `ERROR` with reason `unit_accounting_mismatch` (§4.1, §11). `coverage = aligned_units / total_units`, where `total_units = aligned_units + unaligned_units + unsupported_units`. `unaligned_units` is the sum of the five supported-reason counts (`no_text_match`, `height_mismatch`, `low_overlap`, `ambiguous`, `conflict`); `unsupported_units` is the sum of `unsupported_rotated` and `unsupported_mathtext`. The denominator includes unsupported and unaligned units; the numerator includes only units assigned without an ambiguity. The report records all four counts plus `unaligned_by_reason`, so the ratio is recomputable (§11). The §8 metric is the macro-average of this ratio over holdout samples that have at least one unit; samples with zero units are excluded from the macro-average, counted and reported separately, and are always `UNKNOWN` (§3.2). A sample below 0.90 is `UNKNOWN`; any `unsupported_units > 0` also forces `UNKNOWN` regardless of the ratio (§4.1).

**Use of evidence.** High-confidence findings and the ordinary medium cases in every class use only aligned character boxes: D1's boundary test, D2's single-artist and joint character-box coverage, D3's ratio on the aligned character-box unions `U_1` and `U_2` (recorded as `char_unions` in `evidence.operand_set`), and D4's per-character evidence. Two explicitly medium cases do not need alignment: D3's source-bbox ratio when at least one member cannot be aligned (it records `source_bboxes` as its operand set in `evidence`), and D4's proven-missing unit that has no unique alignment even after the missing-glyph procedure (it records the transformed source bbox as its evidence). Both are bounded as medium in §4 and never become high-confidence findings. The operand set is chosen per pair: if both units are aligned the pair uses `char_unions`, and if either member is unaligned the whole pair uses `source_bboxes`. An unaligned unit cannot contribute to D2 coverage, to D3 char-union overlap, or to a high-confidence D1 finding; D1 has no unaligned path.

**Determinism.** All geometry is float64 PDF points; decisions use unrounded values, and rounding to 0.1 pt happens only for report display and duplicate keys (§7). There is no randomness. Changing this algorithm changes the result and therefore requires a new prereg version once the holdout exists.

## 8. Metrics and release gates

All metrics are computed on the sealed holdout. Wilson intervals are reported for every proportion but are **descriptive only**, because samples cluster inside 12 templates; the template-cluster bootstrap below is the uncertainty statement that must accompany any result.

| Metric | Definition | Gate |
|---|---|---|
| High-confidence precision | matched high-confidence findings / all high-confidence findings | ≥ 0.95 |
| End-to-end recall | matched reference defects / all 96 reference defects | ≥ 0.80 |
| Sample-level UNKNOWN rate | holdout samples with state UNKNOWN / 114 | ≤ 0.20 |
| Sample-level ERROR rate | holdout samples with state ERROR / 114 preregistered holdout samples; invalid inputs and missing-font samples remain in the denominator | ≤ 0.05 |
| Text alignment coverage | macro-average over holdout samples with at least one unit of `aligned_units / total_units`, where `total_units = aligned + unaligned + unsupported` (§7.1); zero-unit samples are excluded from the macro-average, counted separately, and are `UNKNOWN` | ≥ 0.90 |
| Clean/counterexample behaviour | holdout clean and counterexample samples (18) that end in `PASS`; none may end in `FAIL` | ≥ 16/18 PASS and 0 FAIL |
| Incremental value over the strongest fair baseline | end-to-end recall at precision ≥ 0.95, minus baseline B's best recall on the same holdout whose own precision is ≥ 0.95 (§9); the UNKNOWN rate in the secondary clause is the detector's own, because B has no UNKNOWN state and its rate is 0 by construction (§9) | ≥ +0.10 absolute; or ≥ +0.05 with the UNKNOWN rate ≤ 0.05 |
| False positives per page | high-confidence FP findings / pages (one page per sample) | report only; precision is the gate |
| Runtime | CPU wall-clock per sample, median and p95 over 3 runs | report only; no speed claim without a measured baseline |

If no holdout sample has at least one text unit, coverage is undefined and the coverage gate fails; it cannot pass by having nothing to measure.

**Baseline sweep.** Baseline B's two thresholds are swept over a fixed grid — page margin {0, 0.5, 1, 2} pt and source-bbox overlap ratio {0.15, 0.30, 0.50, 0.75} — and its strongest point at precision ≥ 0.95 is used for the delta. The grid is fixed here, before holdout generation. If no baseline point reaches precision ≥ 0.95, the baseline is reported as having no admissible operating point and the delta gate is failed, not skipped.

**Uncertainty.** Resample the 12 holdout template families with replacement and, independently, the 6 holdout counterexamples with replacement; 10,000 draws from `numpy.random.default_rng(0)` (PCG64). Within one replicate the draw order is fixed: first 12 family indices with replacement from the holdout template IDs sorted ascending, then 6 counterexample indices with replacement from the holdout counterexample IDs sorted ascending, each as `Generator.integers(0, n, size=n)` on that one generator instance. Percentiles are `numpy.percentile(values, [2.5, 97.5], method="linear")`. A drawn family contributes **all** of its samples as one block — its clean sample and its eight defect samples — so the clean sample travels with its family and samples are never resampled independently within a family. A family drawn k times contributes k copies; a counterexample drawn k times contributes k copies (multiplicity counts). Recompute each statistic from the drawn observations, never from an average of per-family ratios:

- precision = pooled matched high-confidence findings / pooled high-confidence findings;
- recall = pooled matched references / pooled references;
- UNKNOWN rate = pooled UNKNOWN samples / pooled samples;
- ERROR rate = pooled ERROR samples / pooled samples;
- coverage = arithmetic mean of the per-sample ratios defined in §7.1 over drawn samples with at least one unit (each drawn sample, including duplicate draws, counts once; zero-unit samples are excluded);
- clean/counterexample gate = pooled PASS and FAIL counts over the drawn clean samples and counterexamples.

Counterexamples contribute to precision, the UNKNOWN/ERROR rates, coverage, and the clean gate, but not to recall because they contain no references. If a draw has a zero denominator for a statistic, that statistic is marked undefined for the draw and excluded from its percentile range; the number of undefined draws is reported. Report the 2.5–97.5 percentile range next to every gate verdict. The gates are evaluated on point estimates, as preregistered, and no significance claim is made from these data.

**Reporting rules.**

- Report per-class precision/recall and pooled numbers. Do not pool classes to hide a weak class.
- Report both end-to-end recall and conditional-on-decidable recall; the gate uses end-to-end only.
- Report UNKNOWN and ERROR relative to all holdout samples, not only the decidable subset.
- With 24 reference instances per class (12 templates × 2 seeds), class-level intervals are wide; class-level numbers are descriptive, the pooled gate is binding, and no class-level performance claim may be made from this benchmark.
- Never convert `UNKNOWN` to `PASS` to improve a score. Never exclude a hard sample after seeing results.
- The gates are conjunctive: all must hold. No composite score.

**Status of the gates.** These are initial product gates, not measured results. They may be revised only by a new prereg version before holdout unsealing, with the reason recorded.

## 9. Baselines

Baselines get the same inputs, fonts, page size, DPI, and source manifest. No baseline is given a deliberately bad configuration.

| Baseline | What it does | What it can detect |
|---|---|---|
| A. Matplotlib warnings | captures missing-glyph and layout warnings from the same save | D4 only; no geometry |
| B. Source-bbox rules | the algorithm specified below: source-only rules for all four classes, swept on the fixed grid | D1/D2/D3/D4 candidates from source geometry; expected false positives on legal bboxes and on cases where the bbox is larger than the ink |
| C. Layout mitigation | re-renders with `constrained_layout` and (where applicable) adjustText, then checks whether the defect remains | mitigation rate, not a detector |
| D. Diff against a clean baseline | pixel/PDF diff when a clean export of the same figure exists | changed regions only; not applicable without a baseline |

**Baseline B algorithm.** Baseline B is fully specified here, before holdout generation. It is deterministic, sees only the wrapper's source manifest (the §2 transform, font files, paint order, and recorded save warnings), and never reads PDF text, character boxes, or bitmaps. It enumerates units with the same predicate as §7.1, so rotated and mathtext units are out of scope for B as well, and transforms every supported unit's source bbox to PDF points. At every grid point `(m, r)` it emits four rule families, all `high` confidence:

1. **D1, page margin `m`:** flag a unit whose transformed source bbox is not contained in the page rectangle inset by `m` pt on every side. `m` ∈ {0, 0.5, 1, 2}.
2. **D2, fixed rule:** flag a unit whose transformed source bbox is covered ≥ 0.90 by one artist with effective alpha `α_eff ≥ 0.95` (§4 D2's product of facecolor alpha and artist alpha) and a later recorded paint order, whose filled extent is a rectangle or an image extent. The detector uses aligned character boxes instead; B uses the coarser source bbox.
3. **D3, overlap ratio `r`:** flag every unordered pair of distinct supported units whose transformed source bboxes satisfy `intersection area / smaller bbox area ≥ r`. `r` ∈ {0.15, 0.30, 0.50, 0.75}.
4. **D4, fixed rule:** §4's D4 evidence without the alignment step — the §4 D4 glyph test in every resolved font (the code point is absent from its Unicode cmap or maps to glyph ID 0), plus a recorded save warning naming the character and a resolved family.

Findings carry the §7 identities (one source ID for D1/D2/D4, both IDs for D3) and boxes equal to the transformed source bbox (for D3, the intersection of the pair's bboxes). Class precedence is applied per object in the order `D1 > D4 > D2 > D3` with §4's confidence scoping. Every B finding is high confidence, so on this baseline the scoping reduces to: a pair is suppressed if either member has a higher-precedence high-confidence finding. B emits no medium findings, so no cross-confidence suppression case arises. Matching, precision, and recall use §7 unchanged.

**B's sample state.** B's state for a sample is `FAIL` if it emits at least one high-confidence finding and `PASS` otherwise. B has no `UNKNOWN` state: it never reads the rendered PDF or aligns text, so it cannot discover that its own source evidence is insufficient. Its holdout UNKNOWN rate is therefore 0 by construction, and §8's secondary delta clause is a bound on the detector's own UNKNOWN rate (≤ 0.05), not a comparison B could lose.

**Selection of B's operating point.** The 16 grid points are evaluated on the holdout after unsealing. The chosen point has the highest end-to-end recall among points with precision ≥ 0.95; ties break to the smallest `m`, then the smallest `r`. Selecting the point after seeing holdout outcomes can only strengthen the baseline, so the delta gate stays conservative; the detector's own thresholds are frozen before unsealing (§6). If no point reaches precision ≥ 0.95, B has no admissible operating point and the delta gate fails, not skips (§8).

**Which baseline counts.** Baseline B is the strongest fair detector baseline, because it sees the same source geometry and can be thresholded. The delta gate in §8 is measured against B only. Baseline A is a lower bound (D4 only, layout warnings only) and is reported for context. Baseline C measures mitigation, not detection, and cannot enter a precision/recall delta. Baseline D requires a clean export that the evaluated sample does not have; its "not applicable" is reported, not treated as a zero.

## 10. Stop rule

The full-format route stops if **two recorded algorithm iterations** fail to produce a useful gain over baseline B on the dev split. A useful gain is one of:

- +0.10 absolute end-to-end recall at precision ≥ 0.95; or
- +0.05 absolute recall with the detector's own UNKNOWN rate ≤ 0.05.

**Baseline B's dev comparison point.** An iteration compares against B at the operating point selected by §9's rule applied to the dev split: the point with the highest dev end-to-end recall among the 16 grid points whose dev precision is ≥ 0.95, ties to the smallest `m`, then the smallest `r`. The point is recomputed from the frozen baseline B algorithm on the current dev samples and recorded with the iteration; it is not carried over from a previous iteration. If no dev grid point reaches precision ≥ 0.95, B has no admissible dev operating point, the delta cannot be computed, and the iteration counts as a failed iteration — the same conservative reading as §8's holdout clause. The secondary clause's UNKNOWN rate is the detector's own dev UNKNOWN rate; B has no UNKNOWN state and its rate is 0 by construction (§9), so that clause bounds the detector, not the baseline.

**What counts as an iteration.** One recorded algorithm iteration is a numbered change to the detector's decision logic (rule, threshold, alignment, or evidence aggregation) that is committed with its dev-set result and its diff, after which the dev-set metrics are recomputed. Re-running the same code, changing only comments, refactoring without changing behaviour, adding templates, or regenerating samples with the same seeds does not count. At most two such iterations may be spent trying to beat baseline B; the second failed attempt triggers the stop.

**Development data.** Iteration decisions use only the dev split: 12 templates, 108 dev samples, 96 dev defect instances, and the 6 dev counterexamples. Holdout samples are not generated until B2 and are never used to choose a parameter (§6). The benchmark composition is fixed in §5; adding templates or classes after an iteration starts requires a new prereg version.

If the rule triggers, keep the benchmark/plugin or contribute the rule upstream; do not keep expanding formats to chase a launch. The stop decision and its evidence are recorded in the handover. No amount of growth pressure justifies turning `UNKNOWN` into `PASS`.

## 11. Report and evidence contract

Every run writes a JSON report and, optionally, a local HTML report.

**JSON (minimum fields).**

```
schema_version, tool_version, input_sha256, source_manifest_sha256,
matplotlib_version, pdfium_version, page_count, page_size_pt, rotation,
overall_state (PASS|FAIL|UNKNOWN|ERROR),
coverage {source_units_total, total_units, aligned_units, unaligned_units,
          unsupported_units, unaligned_by_reason {reason: count}, ratio},
zero_unit_samples,
findings [ {sample_id, renderer_version, input_sha256, rule_id, defect_class,
            source_object_id, related_source_object_id, confidence, state, page,
            box_pdf_points, source_text, evidence, reason} ],
unknown_objects [ {source_object_id, reason} ],
errors [ {stage, message} ],
timing {wall_ms}
```

`coverage.source_units_total` must equal `coverage.total_units = aligned_units + unaligned_units + unsupported_units`; otherwise the sample is `ERROR` (`unit_accounting_mismatch`). `source_units_total` is copied from the wrapper's source manifest, so a detector that silently drops units cannot produce a valid report. `unaligned_by_reason` records all seven reasons listed in §7.1: its five supported-failure keys sum to `unaligned_units`, and its two `unsupported_*` keys sum to `unsupported_units`. Any `unsupported_units > 0` forces the sample to at least `UNKNOWN` (§4.1). `ratio = aligned_units / total_units`; it is `null` exactly when `total_units = 0`, in which case the sample is `UNKNOWN`, is excluded from the §8 macro-average, and increments the run-level `zero_unit_samples` count. A reader must be able to recompute `ratio` from the counts; a report whose counts do not add up is invalid and its sample state is `ERROR`.

Every D3 finding carries both `source_object_id` and `related_source_object_id`, normalized so the smaller ID is `source_object_id`; D1/D2/D4 findings set `related_source_object_id` to `null`. `box_pdf_points` follows the per-class definition in §7, so a reader can recompute it from the reported evidence without guessing which union or intersection was used.

`evidence` is an object whose operands make `box_pdf_points` and the coverage recomputable without rerunning the detector. At minimum it carries, per class: D1 — the page rectangle and, for every boundary-evidence box, the character box, its area, its inside area, and its center; D2 — the aligned character boxes `T`, and for every contributing artist its `source_object_id`, rectangle `R_a`, the intersection boxes `T ∩ R_a`, and its own coverage of `T`, followed by the joint coverage, the alpha test used (`α_eff` with both factors, or the recorded image opacity and artist alpha), and that artist's geometry fields (`path_kind`, `path_is_concave`, `fancybox`, filled area, and the inside-page test); D3 — both operands and `operand_set` (`char_unions` with both aligned character-box unions `U_1` and `U_2`, the default for an aligned pair; `source_bboxes` with both transformed source bboxes for the unaligned medium case), the intersection box, the character-box pair that meets the 0.5 pt rule or the fact that none does, and the own-background `owner_unit_id` with its `R_a`; D4 — the code point, the per-font cmap status (present with a non-zero glyph ID, or absent / glyph ID 0) for every resolved font, the resolved font families, the recorded warning text, and the transformed source bbox. A finding whose evidence is missing an operand is invalid and is not counted as a TP.

Each finding must be reproducible from the input hash, tool version, and renderer version. The HTML report is local-only, escapes all source text, embeds crops as data URIs (no remote assets), and shows coverage and unknown objects next to findings. A `PASS` with coverage below the gate is not allowed: the state becomes `UNKNOWN`.

## 12. Security and privacy

- Local processing only; no telemetry, no network, no remote fonts or scripts in the report.
- PDFs are untrusted: page-count, page-size, render-pixel, and wall-clock limits; render subprocess timeout kills only its own PID. A normal subprocess is not claimed to be a strong sandbox.
- PDFium calls are serialized in-process; parallelism only across processes.
- Reports may contain private text; the user must review before sharing. The project does not upload reports.
- No arbitrary-path HTTP server, no filesystem crawling, no execution of code embedded in input files.

## 14. Known limitations

- Only Windows 11 + Python 3.12.3 + Matplotlib 3.10.8 + PDFium 149.0.7825.0 is verified. Other versions may change char boxes or text extraction; results are pinned to the recorded versions.
- The benchmark pins `pdf.fonttype=42`, DPI 100, 10 × 6 in, ASCII minus, and `transparent=False`. Type 3 is supported for ASCII in the product, but no benchmark sample uses it, so type-3 behaviour (including its measured dropping of U+2212) is covered by the §0 owner probe listed in §16, not by the spike artifact and not by detector metrics. Different figure sizes change the dense-tick geometry (§5) and are outside the frozen benchmark; so does a different tick binding for H07, which is why the manifest pins one. The frozen contract fixes the binding, the 10 × 6 size, and the generator's clean check, not any per-size coverage value.
- The benchmark is synthetic and small. 228 samples and 96 holdout defect instances are enough for initial gates, not for a claim about real-world figures.
- The holdout is a template-family split, not an independent random sample. Line charts and shared fonts appear on both sides.
- Text extraction is not rendering evidence. A character can be present in the PDF text stream while its glyph is missing.
- Bounding-box intersection is not occlusion. v1 requires an opaque artist, a later recorded paint order, and ≥90% coverage; semi-transparent cases remain `UNKNOWN`.
- Rotated text, mathtext, path text, multi-page PDFs, and arbitrary PDFs are out of scope. Rotated text and mathtext are still `Text` units: they are recorded as `unsupported_*`, stay in the coverage denominator, and force `UNKNOWN`. Path text is not a `Text` object; it is not enumerated and the report does not claim to have checked it. Multi-page PDFs are rejected as `ERROR` under §2. None of these can produce a supported finding, and none is silently reclassified as clean.
- Alignment failure modes are visible, not hidden. Supported units that fail alignment are recorded as `no_text_match`, `height_mismatch`, `low_overlap`, `ambiguous`, or `conflict`; units excluded by scope are recorded as `unsupported_rotated` or `unsupported_mathtext`. All of them stay in the coverage denominator, and coverage < 0.90 forces `UNKNOWN` for the figure. Unit accounting is reconciled against the wrapper: the wrapper reports `source_units_total` independently of the detector (§7.1), and if `aligned + unaligned + unsupported` does not equal it the sample is `ERROR` (`unit_accounting_mismatch`). A detector that silently drops a unit therefore produces `ERROR`, not a high coverage ratio and not a `PASS`. This check only detects undercounting relative to the wrapper's enumeration; a wrapper bug that never enumerates a unit is outside its reach and would need the B2 label-review evidence to surface.
- PDFium returns zero-area character boxes for CR and LF and for the spaces separating x tick labels (measured: 2 of 125 characters on a title-only fixture, 21 of 180 when six x tick labels share the page). §4's boundary predicate ignores them by definition, and the executable probe `spikes/b0_d1_boundary_probe.py` records both the corrected result (0 high, 0 medium on every fixture) and the fact that the literal round-7 §7 wording flags every one of those boxes while the round-7 §4 wording flags none. A detector that reintroduces an "at least 50% outside" test without the positive-area guard reports clean figures as clipped. Spaces inside ordinary text carry a hairline positive-area box rather than a zero-area box (measured on `"a b"` at the pinned 10 pt binding: 3.18 pt wide × 0.009995 pt tall, area 0.0318 pt²; owner probe recorded in `docs/reviews/B0_REVIEW.md`, Round 11), so the guard must be "area = 0", not "area is small".
- Only horizontal text is supported in v1. Every template's axis labels, shared/twin y-labels, and colorbar label are bound to `rotation=0` and to the §5 alignment binding (left y-labels `ha='right'`, right/twin y-labels `ha='left'`, `supylabel` `ha='left'`), so the expected clean and counterexample states are reachable. Rotation alone is not enough: a horizontal label at default alignment overlaps its own tick labels (measured in §5) and would make a clean sample `UNKNOWN` or `FAIL`. A figure using Matplotlib's default vertical ylabel contributes an `unsupported_rotated` unit and can therefore at best be `UNKNOWN`; this is a scope limitation of v1, not a detector failure, and the benchmark does not measure real-world coverage of default-styled figures.
- Tight-bbox exports are supported only through the wrapper-recorded origin (§2). If a bundle declares `bbox_inches='tight'` but has no recorded origin, the transform is undefined and the result is `UNKNOWN`; the detector never guesses the crop.
- Two dev counterexamples are expected `UNKNOWN` by design: L04 (rotated annotation) and L06 (semi-transparent occlusion). The six holdout counterexamples are expected `PASS`. The §8 clean/counterexample gate counts only the 18 holdout clean and counterexample samples; a `FAIL` on any of them fails that gate. A `FAIL` on a dev counterexample is a B2 development defect recorded in the iteration log, not a §8 gate result.
- Holdout samples are not generated at B0. Only the split, sealing rules, and label expectations exist; the sealed files are produced at B2 and never tuned against.
- Font availability changes results. CJK samples require an OFL CJK font; proprietary fonts are excluded from public artifacts.
- Pillow is a direct runtime dependency (MIT-CMU) used for pixel crops and PNG evidence; Matplotlib already requires it, and the dependency is recorded rather than assumed transitive.
- No real user, star, or time-saving claim exists yet. B4 requires external minimal cases; if none are obtained, the handover must say so.

## 15. Change control

- Typo and clarification edits are allowed with a version bump and a changelog line; they must not change semantics.
- The reviewed revision is pinned by `docs/B0_FREEZE.sha256` and the `b0-freeze-r14` tag. Editing any pinned file invalidates that freeze; a re-review requires a new tag and a new freeze manifest.
- Any change to defect definitions, support scope, split, matching, metrics, or gates after holdout generation requires a new prereg version and a full rerun. Old results are archived, not deleted.
- The sealed holdout is unsealed at most once per prereg version. The unsealing timestamp, evaluation script hash, and input seal hash are recorded.
- If a gate fails, the result is published as a failure. The project may iterate on the dev set and rerun a new prereg version, but may not relabel the holdout to pass.
